# future/ — Parity Tracking & Feature Pipeline

This directory tracks the continuous process of incorporating Anthropic's
latest features into claw-code-parity.

## Structure

```
future/
├── README.md              ← You are here
├── IMPROVEMENTS.md        ← Versioned changelog of all parity improvements
├── manifest.json          ← Machine-readable feature status (read/written by parity-sync.py)
├── docs/                  ← Detailed summaries of changes pulled per version
│   ├── v0.1.0.md         ← First release: adaptive thinking, skill execution, Opus 4.7
│   └── v0.2.0.md         ← (future) Next release
└── audits/                ← Timestamped audit reports generated by parity-sync.py
    └── audit_0.1.0_*.md  ← Audit snapshots with coverage, gaps, and test results
```

## Workflow

1. **Anthropic releases a new feature** (model, API parameter, tool type)
2. **Add to the feature catalog** in `scripts/parity-sync.py`:
   - `ANTHROPIC_FEATURE_CATALOG` — feature name, API param, docs URL, priority
   - `FEATURE_SIGNATURES` — regex patterns to detect implementation in source code
3. **Run the audit:** `python3 scripts/parity-sync.py audit`
4. **Review the gap report** at `future/audits/`
5. **Implement the feature** in `src/`
6. **Re-run the audit** to verify coverage increased and tests pass
7. **Bump version** in `future/manifest.json`
8. **Add version block** to `future/IMPROVEMENTS.md`
9. **Create docs summary** at `future/docs/vX.Y.Z.md`
10. **Commit and push**

## Quick Commands

```bash
# Current status
python3 scripts/parity-sync.py status

# Full audit (scan + test + report + manifest update)
python3 scripts/parity-sync.py audit

# Feature scan only
python3 scripts/parity-sync.py check

# View past reports
python3 scripts/parity-sync.py history
```

## Versioning Convention

- **Major (X.0.0)** — Architectural changes (e.g., multi-agent support)
- **Minor (0.X.0)** — New Anthropic features incorporated
- **Patch (0.0.X)** — Bug fixes, pattern refinements, doc updates

Current version: see `manifest.json` → `current_version`
